# 実行時の構成

自然言語の処理と物理フィードバックを分離する。

```text
一文の指示 → LLM / rules → 条件検証・不足のみ確認 → 経路・world生成
                                                        ↓
                    状態取得 ← Gazebo ← 速度指令 ← 制御器
                       └→ 滑り監視 → 安定後の短履歴予測 ┘
```

`mission_dialogue.py` は回答を保持し、未指定の任意の物理情報は追加質問しない。
明示された数値や否定・訂正・曖昧な地点は検証する。LLMは自由な制御値やシェル命令を出力しない。
`mission_execution.py` は指示から方針の上限を設定し、現行の制御器へ接続する。
荷物名から摩擦・質量・重心を正解として与える処理はない。寸法等の仮設定はシミュレーションに使う。

`controller.py` の役割は以下の通り。

- PathFollower：経路上の位置、目標方向、ゴール状態。
- ObservationController：因果的な観測バッファ、穏やかな発進、実測5 mm超過時の停止。
- HoldController：滑り速度1 mm/s以上なら加速を止め、0.5秒継続時は穏やかに減速。
- ShortHistoryController：滑り速度0.5 mm/s以下が0.5秒続き、ズレ変動0.2 mm以下・現在ズレ4 mm以下なら、保持・0.15・0.30 m/s²の候補を比較。

候補は発進の観測や言語で指定した上限を超えない。現在ズレ＋予測追加量＋校正余裕を5 mm以内にする候補から、進行とズレの評価で選ぶ。
候補がすべて不適合なら保持して実測監督を継続する。保持が安全という証明ではない。
初回発進・最終減速には予測を使用しない。

`predictor.py` は現在・0.15・0.30・0.45秒前の10状態と4指令、計44特徴を使う。
状態は実速度・旋回速度、前の速度・旋回指令、箱の前後・左右ズレ、相対速度、roll・pitch。
摩擦・寸法・質量・荷物ID・重心の真値は入力しない。重みは走行中に更新しない。
採用していない持続記憶や旧方式の分岐・依存は実行コードから除いた。

`simulation.py` は物理を0.05秒ずつ進め、観測時刻を揃えてROS 2のサービスとトピックを使う。
計算中の停止を含むため、現時点の時間や制御は実時間の性能保証ではない。
ログは停止・未到着も到着とは区別して保存する。

学習済みモデルのファイルは採用時のハッシュを維持している。互換性のため未採用variantのデータもファイル内に残るが、実行時はshortだけを参照する。
過去の実験コードをインポートする経路や、`base.fixed.pilot` のような多段の参照はない。
